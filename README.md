# Learning FPGA Dev

A running log of me learning digital design in Verilog, one combinational building block
at a time. Every block has its own folder containing the design module, a self-checking-by-eye
testbench, and (for most) a dumped waveform.

Everything here is plain Verilog-2005 simulated with **Icarus Verilog** — no vendor toolchain,
no board-specific constraints yet. The point so far has been to get the logic right and to see
it move on a waveform.

## Toolchain

| Tool | Version used | Purpose |
| --- | --- | --- |
| [Icarus Verilog](https://steveicarus.github.io/iverilog/) | 12.0 | Compile + simulate |
| [GTKWave](https://gtkwave.sourceforge.net/) | 3.3.100 | View the `.vcd` waveforms |

## Running a testbench

Each testbench uses `` `include `` with paths relative to its own folder, so **`cd` into the
folder first**, then compile and run:

```sh
cd decoders
iverilog -o n_decoder_tb.out n_decoder_tb.v   # compile the testbench (it includes the design)
vvp n_decoder_tb.out                          # run it — results print to the terminal
gtkwave n_decoder_tb.vcd                      # optional: inspect the waveform
```

Substitute the testbench name for whichever block you want. The full list is in the table below.
Only the testbench needs to be passed to `iverilog`; each one includes the design file(s) it needs.

The committed `.v.out` files are Icarus compiler output and the `.vcd` files are simulation
waveforms — both are regenerated by the commands above.

## What's in here

Roughly in the order I built them, since each one leans on the last.

| Folder | Design | Testbench | What it is |
| --- | --- | --- | --- |
| [half_adder/](half_adder/) | `half_adder` | `half_adder_tb.v` | Sum = `a ^ b`, carry = `a & b`. Pure dataflow, the starting point. |
| [full_adder/](full_adder/) | `full_adder` | `full_adder_tb.v` | Structural: two `half_adder` instances plus an OR on the two carries. First time composing a module out of smaller ones. |
| [ripple_carry_adder_N/](ripple_carry_adder_N/) | `rcN_adder` | `ripple_carry_N_adder_tb.v` | Parameterized `N`-bit adder. A `generate` loop instantiates N full adders and threads the carry chain through a `wire [N:0]`. Testbench exercises it at N = 4. |
| [muxes/](muxes/) | `mux_2to1`, `mux_4to1`, `mux_8to1` | `muxstb.v` | 2:1 as a ternary `assign`; 4:1 and 8:1 as a `case` inside `always @(*)`. |
| [demuxes/](demuxes/) | `dmux_1to2`, `dmux_1to4`, `dmux_1to8` | `demux_tb.v` | Built hierarchically — the 1:4 is three 1:2 demuxes, the 1:8 is a 1:2 feeding two 1:4s. Uses `` `ifndef `` include guards so the shared files only get pulled in once. |
| [decoders/](decoders/) | `n_decoder` | `n_decoder_tb.v` | Parameterized N-to-2^N decoder. One-hot output via `1 << in` instead of an explicit truth table. Testbench runs it as a 2-to-4. |
| [encoders/](encoders/) | `_encoder8to3` | `encoder_tb.v` | Plain 8-to-3 encoder from OR gates on the input bits. Assumes a one-hot input — it can't tell `in = 0` from `in = 1`, since both give `000`. That limitation is what motivated the next one. |
| [encoders/](encoders/) | `priorityEn8_3` | `priority_tb.v` | 8-to-3 priority encoder using `casez` with `?` wildcards to pick the index of the *highest* set bit, so multi-hot inputs resolve cleanly. |
| [comparator/](comparator/) | `mag_comp_N` | `mag_comp_tb.v` | Parameterized N-bit magnitude comparator with three outputs: `a < b`, `a == b`, `a > b`. Tested at N = 4. |

## Conventions I settled on

- **Design and testbench live side by side**, named `<thing>.v` and `<thing>_tb.v`.
- **Testbenches print rather than assert.** Most use `$monitor` to trace every input change;
  the earlier ones use `$display` after a `#10` settle. Checking is still done by eye against
  the truth table.
- **Waveforms** are dumped with `$dumpfile`/`$dumpvars` in most testbenches so behaviour can be
  confirmed in GTKWave, not just in the console.
- **Parameterize where the width is the interesting part** — the adder, decoder, and comparator
  are all `#(parameter N)` modules that the testbench instantiates at a concrete width.

## Where this is going
